# Secret inventory and handling

Last updated: 28 August 2026.

Total is offline-first. This inventory is the release checklist for every credential-like value;
no new secret may be introduced without adding its storage, encryption, exposure and rotation path
here.

| Secret | Storage | Protection at rest | Renderer exposure | Backup / diagnostics behavior | Rotation |
|---|---|---|---|---|---|
| Local user PIN | Company SQLite `users.pin_hash` | Salted password hash; original PIN is never retained | PIN input only; never returned | Hash is present in database backups; excluded from diagnostics, logs, mirrors and exports | Owner sets a new PIN |
| AI provider API key | Device-level `ai-provider.json` | Electron OS-backed `safeStorage`; file mode `0600`; crash-safe atomic write | Only `hasApiKey`; key is never returned | Excluded from company backups, mirrors, logs and support diagnostics | Replace or clear in Settings → AI copilot |
| Codex / ChatGPT credential | Owned by the installed Codex CLI, outside Total | Codex CLI credential storage | Total sees only login status and bounded device-login output; it never reads the credential | Never included in Total books, backups, mirrors, logs or diagnostics | Use Codex CLI logout/login; Total stores nothing to rotate |
| AI Operator approved roots | Device-level `ai-operator.json` | File mode `0600`; contains paths and policy, not provider secrets | Renderer may display the configured paths to owners | Excluded from company backups, mirrors and support diagnostics | Remove a root or disable Operator in Settings |
| AI Operator action approval token | Main-process memory in the retained plan; never persisted | Random 256-bit token bound to one company, user, plan action and ten-minute expiry | Returned only with that action's approval prompt and accepted once | Never enters books, backups, mirrors, logs, diagnostics or support | Single-use; discard the plan or wait for expiry |
| Local MCP access token | Device-level `mcp-access.json` | One-time 256-bit random secret; only its SHA-256 hash is retained in a crash-safe file | Plaintext is returned exactly once at issue time; later views show metadata only | Excluded from company backups, mirrors, diagnostics and MCP audit arguments | Revoke or let expire in Settings → Agent access, then issue a replacement |
| Collaboration user access token | Device-level `collaboration-credentials.json` | Electron OS-backed `safeStorage`; file mode `0600` | Password-style input only; never returned after save | Excluded from company backups, JSON mirrors, logs, diagnostics and support | Reauthenticate the Supabase user and replace the saved token |
| Collaboration refresh token | Same encrypted device credential store | Electron OS-backed `safeStorage`; rotated atomically with the short-lived access token | Password-style setup input only; never returned after save | Excluded from company backups, mirrors, logs, diagnostics and support | Revoke the Supabase session, then reconnect the workspace |
| Collaboration recovery key | Same encrypted device credential store; exported only on explicit owner action | Random 256-bit key protected by Electron `safeStorage` | Shown or copied only after an owner request; cleared through sensitive-clipboard policy | Never uploaded, logged, mirrored, diagnosed or included in company backups | Create a new workspace/key and re-enrol trusted devices |
| Collaboration device signing private key | Same encrypted device credential store | Ed25519 key protected by Electron `safeStorage` | Never exposed to renderer | Excluded from company backups, mirrors, diagnostics and support | Remove the device credentials and enrol it as a new device |
| Collaboration invitation code | Shown once to the owner; backend stores only SHA-256 hash | 256-bit random, expiring, revocable and single-use | Visible only at creation/copy and entry by invitee | Raw code is not logged, backed up or stored by the backend | Revoke or wait for expiry, then issue a new invitation |
| Integration webhook signing secret | Encrypted envelope in company SQLite `webhook_endpoints.encrypted_secret` | Electron OS-backed `safeStorage`; only decrypted in the main process for an attempted delivery | Password input only; endpoint lists return `hasSecret`, never the secret | Company backups contain only the OS-protected envelope; outbox payloads, logs, audits, mirrors and diagnostics exclude it | Pause the endpoint and create a replacement endpoint with a new secret |
| Attachment vault key | Encrypted envelope in company SQLite `meta['attachments.encryption.key']` | Random 256-bit AES key protected by Electron OS-backed `safeStorage`; documents use AES-256-GCM | Never exposed; renderer sees only enabled state and migrated-file count | Encrypted attachments and the protected key envelope are included in company backups; excluded from diagnostics and mirrors | Turn encryption off to decrypt while the current platform key is available, or re-encrypt after restoring |
| Export-signing private key | Device-level `export-signing.json` | Ed25519 private key protected by Electron OS-backed `safeStorage`; public key and fingerprint remain public | Renderer sees status, key ID and public key only | Excluded from company backups and diagnostics; public key is embedded in signature sidecars | Create a new device identity; existing signatures remain verifiable with their embedded public key |
| NIC API password and client secret | Encrypted envelope in company SQLite `meta.nic` | Entire credential object encrypted with Electron OS-backed `safeStorage`; legacy plaintext is upgraded on read | Both secret fields return only `••••••••` | Backups contain only the OS-protected envelope; diagnostics, logs, audit rows and mirrors exclude values | Re-enter in Settings → NIC live filing; another Mac may require re-entry |
| Encrypted-backup passphrase | Process memory during one export/import | Never persisted | Password input for the active operation only | Not included in the resulting archive, logs or diagnostics | Create a new encrypted export with a new passphrase |
| Intake administration secret | Vercel environment (`INTAKE_ADMIN_SECRET`) | Hosting provider secret store; never shared with providers | Never reaches browser or desktop app | Not part of app data or diagnostics | Rotate in hosting and release-monitor environments |
| Intake HMAC secret | Vercel environment (`INTAKE_SECURITY_SECRET`) | Hosting provider secret store; required with shared intake storage | Never reaches browser or desktop app | Only keyed digests are stored; the key is not backed up or logged | Rotate after draining short-lived dedupe/rate records |
| Retention cron secret | Vercel environment (`CRON_SECRET`) | Hosting provider secret store | Never reaches browser or desktop app | Not part of app data or diagnostics | Rotate in Vercel cron configuration |
| Support/feedback/cohort provider bearer secrets | Vercel environment (`SUPPORT_PROVIDER_SECRET`, `FEEDBACK_PROVIDER_SECRET`, `COHORT_PROVIDER_SECRET`) | Hosting provider secret store; one credential per provider | Never reaches browser or desktop app | Not part of app data or diagnostics | Rotate independently with the corresponding receiver |
| Supabase intake bearer secret | Vercel `SUPABASE_INTAKE_SECRET` and Supabase Function `TOTAL_INTAKE_SECRET` | Separate provider secret stores; the same value is shared only across these two ends of one server-to-server boundary | Never reaches browser or desktop app | Excluded from cases, feedback rows, logs, evidence and diagnostics | Rotate both providers together, redeploy, then run synthetic intake acceptance |
| Supabase service-role key | Platform-provided Supabase Function environment | Supabase-managed secret store | Never reaches Vercel, browser or desktop app | Never enters Total data, documentation, evidence or logs | Rotate through Supabase and redeploy affected functions |
| Private support-store credential | Vercel project (`BLOB_READ_WRITE_TOKEN` / short-lived OIDC) | Hosting provider secret store; private Mumbai-region Blob store | Server routes only; private objects cannot be read by public URL | Never reaches the browser, desktop app, logs or diagnostic bundles | Rotate or disconnect in Vercel Storage; verify case intake after rotation |
| Support case tracking token | Device-level `support-cases.json`; the website stores only its SHA-256 hash | Random 256-bit token; local file mode `0600`; compared in constant time by the status route | Available only to the local support UI for the selected case | Sent only as the HTTPS status credential; excluded from company backups, mirrors, diagnostics, submission payloads and app logs | Delete the remote case through intake administration and create a new case |

Support diagnostics are deliberately allow-listed, not redacted after collection: only app version,
OS platform and CPU architecture are constructed. The in-app support dialog shows the exact JSON
before submission. IPC logging records channel names and sanitized error messages, never payloads.

The desktop build profile and Supabase project reference are identifiers, not credentials. Staging
artifacts embed only the isolated staging origin and an updater-disabled flag. They must never embed
provider bearer secrets, Supabase user tokens, service-role keys or intake secrets.
